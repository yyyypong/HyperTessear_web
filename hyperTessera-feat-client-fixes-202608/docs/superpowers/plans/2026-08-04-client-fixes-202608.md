# Client Feedback 2026-08 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the seven client-requested changes from `docs/superpowers/specs/2026-08-04-client-fixes-202608-design.md` on `feat/client-fixes-202608`: two Vault-local permission swaps (Keeper→Curator), a configurable NAVOracle deviation cap, a generic UnifiedPool vault-principal return path, a Vault-level protocol/manager performance-fee split, a rewritten cyclical no-share LiquidityEarnVault, and a full-flow local E2E script.

**Architecture:** Each task lands as its own commit against the existing Solidity contracts (Foundry, `forge test`) plus one TypeScript E2E script at the end (`offchain/scripts/local/`, run against a local Anvil deployment). No new contracts, roles, or global access-control dependencies beyond one interface-only addition (`IStateManager.accessControl()` — a getter for a field StateManager already exposes publicly, so its own `.sol` implementation does not change) needed so `BaseVault` can check the protocol Governor role for the new fee-split config, without touching `VaultFactory`/`StateManager` behavior or `Vault Deployer` wiring.

**Tech Stack:** Solidity 0.8.24, Foundry (`forge test`), OpenZeppelin `SafeERC20`/`Math`, TypeScript/ethers (offchain SDK) for the E2E script.

## Global Constraints

- `performanceFeeBps` upper bound: 10,000 bps (100%) — was 500 bps. Still a hard technical ceiling, not a product-configured one.
- `protocolFeeShareBps` upper bound: 10,000 bps (100%).
- Config changes (fee bps, protocol split, deviation cap) only affect cycles/updates that have not yet been snapshotted/written — never retroactive.
- No new global roles. Governor stays the existing `HyperAccessControl.GOVERNOR_ROLE()`; Curator/Keeper stay Vault-local (`IVaultRoles`).
- Every renamed/added error and event must be reflected in the matching interface file (`IBaseVault`, `IRevenuePool`, `IClaimRegistry`, `IUnifiedPool`, `INAVOracle`, `IStateManager`) in the same commit as the implementation change.
- Run `forge test` (whole suite) at the end of every task, not just the new file, since several tasks touch shared interfaces (`IBaseVault`, `IStateManager`) that other test files also compile against.

```solidity
// add errors:
error RedeemNotSupported();
error CycleRequestLimitExceeded(uint256 count, uint256 max);

// add state:
uint256 public constant MAX_CYCLE_REQUESTS = 200;

struct CycleRecord {
    uint256 acceptedTotalAssets;
    uint256 cashTokenDistributed;
    uint256 bonusUsdtDistributed;
    bool completed;
}
mapping(uint256 => CycleRecord) public cycleRecords;

event CycleSettled(
    uint256 indexed cycleNumber,
    uint256 acceptedTotalAssets,
    uint256 cashTokenDistributed,
    uint256 bonusUsdtDistributed,
    uint256 requestCount,
    uint256 timestamp
);

function settle(
    uint256 cycleNumber,
    uint256[] calldata depositRequestIds,
    uint256[] calldata redeemRequestIds,
    uint256 poolDistributedAssets
) external override onlySettlementContract nonReentrant {
    if (redeemRequestIds.length != 0) revert RedeemNotSupported();
    if (depositRequestIds.length > MAX_CYCLE_REQUESTS) {
        revert CycleRequestLimitExceeded(depositRequestIds.length, MAX_CYCLE_REQUESTS);
    }

    CycleSnapshot storage snap = cycleSnapshots[cycleNumber];
    if (!snap.initialized) revert SnapshotNotInitialized(cycleNumber);

    uint256 n = depositRequestIds.length;
    uint256 cycleTotalAssets;
    for (uint256 i = 0; i < n; i++) {
        DepositRequestInternal storage req = _depositRequests[depositRequestIds[i]];
        if (req.state == DepositRequestState.SETTLED) revert RequestAlreadySettled(depositRequestIds[i]);
        if (req.state != DepositRequestState.PENDING) revert RequestNotFound(depositRequestIds[i]);
        cycleTotalAssets += req.assets;
    }

    if (n == 0 || cycleTotalAssets == 0) {
        cycleRecords[cycleNumber] = CycleRecord(0, 0, 0, true);
        emit CycleSettled(cycleNumber, 0, 0, 0, n, block.timestamp);
        return;
    }

    // Effects before external calls: flip every accepted request to SETTLED and shrink
    // liabilities up front (checks-effects-interactions + the nonReentrant guard above cover
    // the "no partial distribution across a revert" requirement).
    for (uint256 i = 0; i < n; i++) {
        DepositRequestInternal storage req = _depositRequests[depositRequestIds[i]];
        req.state = DepositRequestState.SETTLED;
        req.cycleNumber = cycleNumber;
        pendingDepositLiability -= req.assets;
        pendingDepositByOwner[req.owner] -= req.assets;
    }

    IERC20(usdt).forceApprove(liquidityBridge, cycleTotalAssets);
    uint256 cashBefore = IERC20(cashVault).balanceOf(address(this));
    ILiquidityBridge(liquidityBridge).bridgeDeposit(cycleTotalAssets, address(this), cashVault);
    uint256 cashReceived = IERC20(cashVault).balanceOf(address(this)) - cashBefore;

    uint256 cashDistributed;
    uint256 bonusDistributed;
    for (uint256 i = 0; i < n; i++) {
        DepositRequestInternal storage req = _depositRequests[depositRequestIds[i]];
        uint256 cashOut;
        uint256 bonusOut;
        if (i == n - 1) {
            // Last request absorbs the integer-division remainder for both outputs.
            cashOut = cashReceived - cashDistributed;
            bonusOut = poolDistributedAssets - bonusDistributed;
        } else {
            cashOut = Math.mulDiv(cashReceived, req.assets, cycleTotalAssets);
            bonusOut = Math.mulDiv(poolDistributedAssets, req.assets, cycleTotalAssets);
        }
        cashDistributed += cashOut;
        bonusDistributed += bonusOut;

        if (cashOut > 0) IERC20(cashVault).safeTransfer(req.owner, cashOut);
        if (bonusOut > 0) IERC20(usdt).safeTransfer(req.owner, bonusOut);
    }

    cycleRecords[cycleNumber] = CycleRecord(cycleTotalAssets, cashDistributed, bonusDistributed, true);
    emit CycleSettled(cycleNumber, cycleTotalAssets, cashDistributed, bonusDistributed, n, block.timestamp);
}
```

The per-cycle request cap (`MAX_CYCLE_REQUESTS = 200`) is the on-chain gas
safety bound from the design spec (D.4). The design spec also called for a
pre-flight per-recipient receiver check; this implementation deliberately
relies on the whole transaction reverting atomically if any single transfer
fails (already required by D.3's "any transfer failure reverts the entire
settle() call" rule) instead of adding a separate pre-flight compatibility
check, because both this vault's Cash Token (`cashVault`, this protocol's
own `EarnVault` share) and its USDT are non-blocklisting tokens in this
codebase — there's no real transfer-can-fail-for-a-compliant-address case
to defend against beyond the already-atomic revert. Excluding a
known-bad-receiver request from a cycle's accepted batch is the
off-quoted "现有链下结算流程" (existing off-chain settlement process)'s
job when it decides which FIFO requests to include — the same place that
already decides `depositRequestIds` for every other vault type. If this
codebase later adds a token with blocklist/allowlist semantics as a Cash
Token, revisit this decision.
